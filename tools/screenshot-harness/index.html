Merlin's Cloak — screenshot harness

Every view below renders with FICTIONAL fixture data (see mocks/fixtures.ts) — no real router is contacted or required. Resize the browser viewport to 1280×800 before capturing Chrome Web Store screenshots. See README.md in this directory for details.

  • Popup — the toolbar popup (router address + read-only toggle).
  • Content UI — Dashboard — #/dashboard, the Network Map replacement (SDN fixture: network-centric wireless table).
  • Content UI — Dashboard (classic fallback) — ?classic=1#/dashboard, same page with the SDN capability flag off: the original plain per-band wl0/1/2_ssid table.
  • Content UI — Dashboard (dual-WAN) — ?dualwan=1#/dashboard, same page with a second WAN unit active (Failover mode, Primary/Standby cards).
  • Content UI — Connected Devices — #/clients, DHCP leases + live wireless stations.
  • Content UI — DHCP settings — #/dhcp, a representative declarative settings page.
  • Content UI — Separate Networks & Guest Wi-Fi — #/sdn, SDN profile create/edit/delete affordances (writes hard-blocked, preview only).
  • Content UI — QoS Priority Bandwidth Allocation — #/qos-userprio, qos_orates/qos_irates per-band allocation + ACK/SYN/FIN/RST/ICMP boost flags.
  • Content UI — Notification Center — #/notification-center, get_nt_db() event list incl. a read, an unread, and a raw-hex-fallback event.
  • Content UI — AiMesh Node Management — #/aimesh, CAP + two RE nodes (one offline), plus a read-only onboarding candidate.
  • Content UI — Time Machine — #/timemachine.
  • Content UI — Download Master / USB Apps (status) — #/download-master, read-only.
  • Content UI — WireGuard Server — #/wireguard-server, server unit 1.
  • Content UI — WireGuard Server Peers — #/wireguard-server-peers, peer slot 1 of 3 fictional peers.
  • Content UI — Operation Mode — #/opmode, read-only; fixture reads as Router mode.
  • Content UI — Router HTTPS Certificate — #/router-cert, httpd_cert_info() metadata, Let's Encrypt mode.
  • Content UI — VPN Certificates & Keys — #/vpn-certs, OpenVPN/WireGuard cert-key presence badges (writes hard-blocked).
  • Content UI — OpenVPN Server — #/openvpn-server, server 1 (TLS, enabled, username/password client list) vs. server 2 (Static Key, disabled) via the instance selector (writes hard-blocked).
  • Content UI — USB Share Accounts & Permissions — #/usb-accounts, 3 fictional accounts + per-account/pool/folder/protocol share grants (read-only).
  • Content UI — USB Share Accounts & Permissions (no USB disk) — ?nodisk=1#/usb-accounts, "no USB disk detected" degradation path.
  • Content UI — USB Share Accounts & Permissions (no accounts) — ?noaccounts=1#/usb-accounts, zero-accounts empty state.
  • Content UI — USB Share Accounts & Permissions (unrecognized permissions hook) — ?badaccounts=1#/usb-accounts, malformed/unrecognized get_permissions_of_account() response degradation path.

The content UI is one hash-routed app (content.html#/<page-id>); any page id from src/pages/registry.ts can be loaded the same way, though only the routes listed above have fixture data tailored to them — other pages will render with blank fields rather than fixture values.
